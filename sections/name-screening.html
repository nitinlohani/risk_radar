AI & Screening

Name Screening

Navigation Homepage → FT AML → Name Screening

Screens individuals and entities against the LSEG watchlist database to identify potential sanctions, PEP, and adverse media matches.

The module offers four ways to run a screen, used for different situations: Watchlist Search for an ad-hoc, on-demand lookup; Manual Screening for screening one customer with full profile detail during onboarding or review; Batch Screening for re-screening large customer populations on a schedule; and Delta Screening for automatically re-checking only the customers affected when the watchlist itself changes. All four draw on the same matching rules and severity bands set once in Configuration, so a match found through any method is scored and prioritized consistently.

Watchlist Search

Navigation Homepage → FT AML → Name Screening → Watchlist Search

Enables users to search for individuals or entities against the LSEG watchlist database. Used for ad-hoc, on-demand lookups — e.g. screening a customer against an international sanctions list before opening an account.

How to use

  • Enter the Name of the individual or entity in the search box
  • (Optional) Apply additional filters such as Country, PEP Status, Category, or Entity to narrow the search results
  • Click Search or press Enter
  • Review the list of matching records displayed below
Column What it shows
UID The unique identifier for that watchlist record within the LSEG database
Name The individual or entity name as held on the watchlist
PEP Status Whether the record is an Active politically exposed person, or another status such as former PEP
Country The country associated with the record
Category Individual, Organization, or Political Individual/Organization
Date of Birth Where available — many watchlist entries carry only a partial or missing date of birth, which is why Name and Address weightages matter so much for matching
Example

A branch officer searches “John Smith” with Country set to United Kingdom and PEP Status set to Active, to quickly check whether a walk-in customer appears on any current sanctions or PEP list before opening an account.

Record detail — clicking any result row opens the full watchlist record in a modal, organized into four tabs:

  • Profile & Identity — Gender/Type, Date of Birth, Place of Birth, Citizenship, Alternative Spelling, Age, Identification Number, Aliases, IDs/Passports, and Deceased Date
  • Risk & Background — Position, PEP History, Title, Category, Sub-Category, Special Interests, PEP Status, and a Further Information/Biography panel covering biography, identification notes, and dated reports (e.g. arrests, convictions)
  • Network & Locations — Addresses on file, associated Companies, and linked Associates by UID, for tracing related individuals or entities
  • Source — Links back to the original source articles or registers the record was compiled from, for independent verification

Manual Screening

Navigation Homepage → FT AML → Name Screening → Manual Screening

Allows users to screen an individual or entity by manually entering customer information. The system compares the provided details against the watchlist database using configured matching criteria and weightages to identify potential matches. This gives analysts flexibility to screen immediately during investigations, onboarding, periodic reviews, or whenever customer information changes — outside the scheduled automated screening cycle.

How to use

  • Enter the customer's Name
  • Select the Entity Type (e.g. Individual or Organization)
  • Provide additional details such as Gender, Date of Birth, Citizenship, and Address (optional but recommended for more accurate results)
  • Review the matching weightages displayed at the top of the page
  • Click Proceed to Screen to initiate the screening process

After clicking Proceed to Screen, the Screening Details page shows the resulting Matches — the number of hits found, and for each one a side-by-side comparison of the entered details against the watchlist record, with the Weightage and Score contributed by each field (Name, Nationality, Date of Birth, Address, Entity Type) and the overall match score and category (e.g. Low 88.21%, Corporate). Selecting a match confirms it as the record to act on.

The weightage bar at the top of the screen (e.g. Name 60%, Address 20%, Citizenship 10%, Gender 5%, DOB 5%) shows exactly how much each field contributes to the final match score before you screen — set once for the whole institution in Screening Configuration, and simply displayed here for reference on every manual screen.

Example

During onboarding, an analyst manually screens a new corporate client, “Meridian Trading Ltd”, entering its registered address and country of incorporation, and reviews the resulting match score before the account is approved.

Batch Screening

Navigation Homepage → FT AML → Name Screening → Batch Screening

Screens large customer populations at once (e.g. nightly onboarding batches), letting institutions re-screen millions of records efficiently — e.g. running the entire customer base overnight the moment a new sanctions list is received, instead of reviewing customers individually. Batch Screening itself is now a read-only history of past runs — scheduling and triggering these runs is configured from Data Ingestion → Batch Ingestion instead, keeping all recurring-job scheduling in one place across the platform.

How to use

  • Navigate to Batch Screening from the Name Screening menu
  • View the list of past screening runs along with their status
  • Use Search by Run ID, or Show Filters to narrow the list further
  • Monitor run health using the dashboard cards (Total Runs, Processing, Completed, Failed)
  • Click Refresh to pull the latest run status
  • Click a row to open that run's Details panel

The dashboard cards at the top — Total Runs, Processing, Completed, Failed — give an at-a-glance health check before drilling into any one run. Each row in the table then shows:

Column What it shows
Run Date / ID When the run started, plus its unique Run ID reference
Status Screening Success, or a run still in progress or failed
Customers Scanned How many customer records were screened in that run
Alerts How many hits the run produced
Errors Records that failed to process, if any
Duration How long the run took, start to finish

Clicking a row opens that run's Details panel rather than a separate page. It repeats the Customers Scanned, Alerts, and Errors totals, then adds the exact Started, Completed, and Duration timestamps, the Input File the run was screened against, and a Download Results CSV button to export that run's screened records and alerts for offline review or record-keeping.

NoteTo change how often batch screening runs, or to pause/resume it, go to Data Ingestion → Batch Ingestion — Batch Screening no longer has its own scheduling controls.
Example

Each night, the institution's entire retail customer base is submitted as a batch job, so that any new sanctions or PEP list updates are checked against every customer without manual effort. The next morning, a compliance officer opens that run in Batch Screening to confirm it completed cleanly and download the results.

Delta Screening

Navigation Homepage → FT AML → Name Screening → Delta Screening

Automatically re-screens previously screened customers when the watchlist updates — the primary control for continuous, rather than point-in-time, compliance. Only the customers affected by the latest watchlist update are re-screened — e.g. a previously cleared customer is automatically rechecked the moment a new sanctions list is published, without reprocessing the full customer base.

How to use

  • Navigate to Delta Screening from the Name Screening menu
  • Review the scheduled screening runs displayed on the page
  • Use the Search, Status, or Date Range filters to locate a specific screening run
  • Monitor the screening schedule, including Next Run, Last Run, and Current Frequency
  • Click Change Schedule to modify the screening frequency or timing, if required
  • Select a completed run to review customers screened, alerts generated, and execution duration
Column What it shows
Run Date When that scheduled run executed, or Upcoming for the next scheduled run
Customers Scanned How many previously screened customers were affected by the watchlist update and therefore re-checked
Alerts Created New hits produced by that run — often zero, since most watchlist updates don't affect any existing customer
Frequency How often delta screening runs, e.g. Every 2 Days
Status Scheduled, Completed, or a run currently in progress
Duration How long the run took to complete
Example

When a new sanctions list is published, only the customers affected by that update are automatically re-screened overnight, and any new hits appear in the Alert Manager the next morning — with no need to re-run the full customer base.

Configuration

Navigation Homepage → FT AML → Name Screening → Configuration

Controls how strictly a record must match, and how resulting hits are prioritized for review.

Screening Configuration

Navigation Homepage → FT AML → Name Screening → Configuration → Screening

Lets administrators configure the matching criteria and weightages used during screening. Each parameter — Name, Address, Citizenship, Gender, Date of Birth — can be assigned a custom weightage to determine the overall match score, so institutions can align screening sensitivity with their internal AML policies and risk appetite. Higher weightage strictness reduces false positives but risks missing true matches. A parameter can also be expanded into its own sub-criteria — for example Name into Fuzzy and Phonetic matching, or Address into Country, City, Street Address, and Region — for finer control over what drives that parameter's contribution to the score.

How to use

  • Navigate to Configuration → Screening from the Name Screening module
  • Review the active screening configuration and the assigned weightages
  • Click Edit to modify the screening configuration
  • Configure the weightage for Name, Address, Citizenship, Gender, and Date of Birth
  • Expand each section to configure its individual matching criteria
  • Save the configuration to apply the updated screening rules
NoteThe total across Name, Address, Citizenship, Gender, and Date of Birth must always equal exactly 100% — the platform will not save a configuration where the parameters sum to more or less than that. The same rule applies one level down: whenever a parameter is expanded into sub-criteria (e.g. Name split into Fuzzy and Phonetic matching), those sub-weightages must themselves add up to 100% of that parameter's own share, not to 100% of the overall score.

Alert Configuration

Navigation Homepage → FT AML → Name Screening → Configuration → Alerts

Lets administrators configure the alert severity levels generated during screening — defining score ranges, assigning severity levels, configuring SLA deadlines, and enabling auto-hibernation, so organizations can prioritize investigations and standardize alert handling based on risk.

How to use

  • Navigate to Configuration → Alerts from the Name Screening module
  • Review the active alert configuration and its defined severity levels
  • Click Edit to modify the existing alert configuration
  • Configure Alert Name, Score Range (Min % – Max %), No Alert option, SLA Deadline, and Auto Hibernation for each severity level
  • Save the configuration to apply the updated alert settings
  • Select Alert Configuration History to view previously saved configurations
Severity Score Range SLA Deadline Auto Hibernate
Very Low 0% – 75% No alert raised —
Low 75% – 79% 1 day Yes
Medium 79% – 85% 2 days No
High 85% – 90% 3 days No
Very High 90% – 100% 5 days No

A match scoring below the Very Low threshold never becomes an alert at all — it's filtered out automatically. Auto Hibernate on the Low band means a low-severity alert that isn't actioned within its SLA is automatically archived rather than sitting open indefinitely, keeping analyst queues focused on alerts that genuinely need attention. Full configuration history is retained for audit.

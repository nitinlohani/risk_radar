Alert Manager

Navigation FT AML → Alert Manager

Every hit generated anywhere in the platform — a name-screening match, a transaction-monitoring rule firing — lands here first, ranked by severity and SLA deadline, before it ever becomes a case.

Alert Queues

Like Case Manager, alerts are organized into three tabs: My Queue (alerts assigned to the logged-in user), All Alerts (the full institution-wide alert volume — this can run into the tens of thousands), and Admin View (oversight across every analyst's queue, showing Unassigned, Escalated, and SLA Breached alert counts alongside Active Agents data).

How to use

  • Search by Entity name or Alert ID
  • Use Show Filters to narrow by Module, Score, Status, or Assignee
  • Click Refresh to pull newly generated alerts
  • Click a row to open the full alert detail and, if warranted, escalate it into a case

View Case — clicking a row opens the alert's detail screen, showing the match or rule detail that triggered it, the customer or entity involved, and the score breakdown behind it. From here an analyst either clears the alert directly, or escalates it — which creates (or attaches it to) a case and opens that case's own View Case screen in Case Manager for full investigation and disposition.

Alert List Columns

Column What it shows
Entity / Alert ID The customer or subject name, plus a unique alert reference (e.g. ALT-NS-20260717...)
Module Which engine generated the alert — Name Screening or Transaction Monitoring
Score The match or risk score as a percentage, color-coded to the severity band it falls into (Low, Medium, High, Very High) as defined in Alert Configuration
Status Open, or a later workflow state once the alert has been actioned
Disposition The outcome once reviewed — blank while still open
SLA Deadline Shows On Track once the alert is within its configured resolution window, and flags it once that window is at risk of being missed
Assigned To The analyst responsible for reviewing the alert
Created At When the alert was generated

The Score and SLA Deadline columns exist because of how severity bands are set up in Alert Configuration — each band (e.g. Medium: 79–85%) carries its own SLA window, so a higher-scoring alert is automatically given a tighter deadline than a low-scoring one.

Example

An alert scoring 81.19% falls in the Medium band, which — per the institution's configured severity bands — carries a 2-day SLA deadline; an analyst working their queue by SLA Deadline will see this alert before a Low-scoring one with a longer window, even if the Low one was created earlier.

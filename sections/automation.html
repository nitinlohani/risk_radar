Automation

Navigation Homepage → FT AML → Automation

Configures how alerts from Name Screening and Transaction Monitoring automatically become cases in Case Manager — instead of each alert needing to be manually opened into its own case. Automation currently has one configurable area — Case Creation — which controls which alert types are eligible, and how related alerts get grouped together into a single case.

Case Creation — Active Configuration

Every institution has exactly one active Case Creation configuration at a time, shown read-only here until Edit is used. It has two parts: which Alert Types are allowed to trigger automatic case creation at all, and the Alert Type Grouping rules that decide when several alerts should merge into one case instead of each opening a separate one.

Within Alert Type Grouping, each Group lists the Alert Types it applies to (here, Name Screening and Transaction Monitoring together, tagged "2 Sources"), a Case age in days, and a set of Case Status values. Read together, a group says: alerts from these sources, on the same customer, land in the same case as long as that case is still within the Case age window and currently sitting in one of the listed statuses — otherwise a new case is opened instead of merging into an old one.

Editing the configuration

Clicking Edit turns every field in the Active Configuration interactive: Alert Types become checkboxes you can toggle, and each group's Alert Types, Case age, and Case Status become editable directly in place.

How to use

  • Navigate to Automation → Case Creation from the FT AML menu
  • Click Edit in the top right to unlock the configuration
  • Under Alert Types, check or uncheck which sources (Name Screening, Transaction Monitoring) can trigger automatic case creation
  • Within a group, add or remove Alert Types from the Select alert type dropdown
  • Set Case age — the merge window in days: alerts on the same customer arriving within this many days of an existing case join that case instead of opening a new one
  • Set Case Status — which case statuses remain open to merging (e.g. a case that's already Reopened or Escalated can still absorb new alerts; one that's Closed typically shouldn't)
  • Use + Add Group to create additional groupings with their own rules, if different alert-type combinations need different merge behavior
  • Click Save to apply the changes, or Cancel to discard them
NoteSaving a change here doesn't retroactively re-group cases that already exist — it only changes how future alerts are evaluated for merging from that point on.

Configuration History

Every save creates a new version rather than overwriting the last one, so the full history of how case-creation rules have changed over time is always available for audit. Configuration History lists every version — its unique Config Version ID, whether it's the currently ACTIVE one or an INACTIVE past version, when it was created, and by whom.

How to use

  • Click Configuration History at the top of Case Creation
  • Scan the Status column for which version is currently ACTIVE
  • Click any row to open that version's full read-only configuration in a Details panel, exactly as it was saved
Example

A customer triggers a Name Screening alert on Monday and a Transaction Monitoring alert on Wednesday. With both Alert Types in the same group, a Case age of 152 days, and Open included in Case Status, the Wednesday alert joins Monday's still-open case automatically instead of creating a second, disconnected case for the same customer.

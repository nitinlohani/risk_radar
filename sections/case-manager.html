Core Workflow

Case Manager

Navigation FT AML → Case Manager

The workspace where every investigation lives. When an alert from Name Screening or Transaction Monitoring needs a human look, it becomes a case here — either automatically, per the rules set in Automation → Case Creation, or manually — and every action taken on it, from first review to final sign-off, is recorded for audit.

Case Queues

Cases are organized into three views, switchable from tabs at the top of the screen:

  • My Queue — only the cases assigned to the logged-in analyst, so investigators see just their own workload
  • All Cases — every case across the institution, for supervisors and MLROs who need full visibility
  • Admin View — an administrative view across all analysts' queues, showing case counts by status (Unassigned, Escalated, Pending Approval) alongside Active Agents data, so supervisors can rebalance workload or check coverage

How to use

  • Search by Case Title, Case ID, or Customer Name using the search bar
  • Filter by Status, Creation Period, Age Period, or Assignee
  • Click Refresh to pull the latest case data, or Hide/Show Filters to collapse the filter bar
  • Click any row to open the full case file with alert history, findings, and audit trail

View Case — clicking a row opens the case's dedicated detail screen rather than a simple pop-up. From here an analyst can:

  • Review the underlying alert(s) that triggered the case, including the screening or transaction detail behind each one
  • See the customer's full profile alongside prior cases and screening history for context
  • Add investigation notes and attach supporting documents to build the evidence trail
  • Record findings and move the case through disposition — False Match, escalate as a True Match, or Request Info — as covered in Case Lifecycle
  • View the complete audit trail of every status change, note, and user action logged against the case

Add Alerts — a case can grow to cover more than the alert(s) it opened with. Clicking Add Alerts on the case detail screen lets an analyst merge other ungrouped alerts on the same subject into the current case, rather than investigating each one separately:

How to use

  • From the case detail screen, click Add Alerts
  • Search the list of ungrouped alerts (e.g. by entity name) to find related alerts
  • Select one or more alerts to merge into the case
  • Click Add Alerts to confirm — the selected alerts now appear in the case's alert strip and count toward its Alerts total

Case detail tabs — below the customer profile, the case detail screen organizes supporting evidence into four tabs:

  • Analytics — incoming/outgoing transaction summaries (Total, Average, Max) over a selectable window (1D/7D/30D or the alert window), plus Top Counterparties by Amount and a breakdown by Transaction Type
  • Transactions — the customer's full transaction history, filterable by Type, Channel, Price range, Date range, Sender ID, or Receiver ID, with a Triggered Txns toggle to isolate only the transactions that triggered an alert, and an Export CSV option
  • Other Cases / Alerts — every other case and alert on file for the same customer, split into Cases and Alerts sub-tabs, so an analyst can spot a pattern of prior activity before deciding on disposition
  • Rule Analysis — for alerts raised by Transaction Monitoring, shows which rule fired and why; expanding a condition reveals the underlying variable (aggregation function, time window, and group-by field) and the actual value that breached the threshold

Case Lifecycle

Every case moves through the same stages, regardless of which module generated the underlying alert:

Alert Triggered → Investigator Review → Findings Documented → Disposition (False Positive / Escalate for SAR-STR / Request Info) → MLRO Approval → Audit Record

  • Alert Triggered — Name Screening or Transaction Monitoring raises a hit that meets the case-creation threshold, and Case Manager opens a case automatically
  • Investigator Review — an analyst examines the customer, transaction, or match details behind the alert
  • Findings Documented — the analyst records what was checked and why, building the evidence trail for the eventual disposition
  • Disposition — the analyst closes the case as a False Match (no further action), or marks it a True Match to escalate for an SAR/STR filing, or selects Request Info to pause the case pending more information from the business or customer
  • MLRO Approval — for cases escalated toward a filing, the Money Laundering Reporting Officer reviews and approves before submission
  • Audit Record — every stage above, and who performed it, is permanently logged against the case

A case can bundle several related alerts (see the Alerts column in Case List Columns), and each one is individually disposed through the Dispose Alert dialog, opened from within the case:

How to use

  • From the case's detail screen, select the alert to dispose and click Dispose Alert
  • Choose the Disposition — True Match, False Match, or Potential Match
  • Select a Rationale Code that best matches the reason for the decision (e.g. Identification Number Match)
  • Enter Rationale Details — a minimum of 10 characters explaining the finding
  • Attach Supporting Documents if needed (up to 5 attachments, up to 20 MB each)
  • Click Submit Decision to record the disposition against that alert

Case List Columns

The case list surfaces the information an analyst needs to triage their queue without opening every case:

Column What it shows
Case Title / ID The customer or subject name, plus the unique case reference (e.g. CASE-2026-0000087)
Status Where the case currently sits — e.g. STR Created, STR Draft, Reopened, or Closed
Disposition The investigation outcome — True Match, False Match, or blank while still under review
Assigned To The analyst currently responsible for the case
Alerts How many alerts are linked to this case — a case can bundle several related alerts on the same customer
Case Age Days elapsed since the case was created, used to track against internal SLAs
Created At Date and time the case was opened
Example

A case with Status STR Created and Disposition True Match means the analyst confirmed the hit was genuine and an STR has already been filed; a case showing Reopened means it was previously closed but new information brought it back for another look.

Filing an STR

An STR can only be filed once a case reaches the right point in its lifecycle — it isn't available the moment a case is created. The path is: close every alert linked to the case, close the case itself with a True Match disposition, and only then does the platform offer File STR. The walkthrough below follows one real case (Pooja Sharma, CASE-2026-0034617) through all three stages, end to end.

NoteYou cannot file an STR on an Open case, and you cannot close a case while it still has open alerts. Both alerts and the case itself must be disposed of first — the platform enforces this order and will not let you skip a step.

Stage 1 — Dispose of every alert on the case

Open the case from Case Manager. An open case with no disposition yet shows a plain Open status in the case list — this is the starting point before any of the work below happens.

If the case still has an active alert (shown as a card just below the case header), that alert must be resolved before the case can be closed — the Disposition field at the top still reads "Select Outcome" at this point, confirming the case itself hasn't been decided yet.

How to use

  • Review the alert card (match score, watchlist name, screening rule) shown under the case header
  • Click Dispose Alert and record its outcome — repeat for every alert attached to the case if there is more than one
  • Only once all alerts are disposed does the case become eligible to close

Stage 2 — Close the case with a True Match disposition

With alerts cleared, open the case's close-case workflow. The dialog repeats the same rule as a safeguard — "Make sure to close all alerts before making a disposition on this case" — so if anything was missed, this is the last checkpoint before it's caught.

The Rationale Code field records the standardized reason behind the disposition, paired with free-text Rationale Details (minimum 10 characters) explaining the decision in plain language.

Once Disposition, Rationale Code, and Rationale Details are all filled in, Close case becomes clickable.

How to use

  • Under Disposition, choose True Match — this is the specific outcome that later unlocks STR filing (False Match or Potential Match do not)
  • Pick a Rationale Code from the dropdown, and write Rationale Details explaining the decision (10 characters minimum)
  • Optionally attach supporting documents (up to 5 files, 20 MB each)
  • Click Close case once all three required fields are filled in

The case immediately reflects the closure: Status changes to Closed, the Disposition badge shows True Match, and — this is the moment STR filing becomes possible — a new File STR button appears next to Re-Open.

Stage 3 — File the STR

Clicking File STR opens a 6-step wizard that assembles a GoTRACS-compliant Suspicious Transaction Report. Each step must be completed before moving to the next; progress is tracked across the top of the dialog.

Step 1 — Select Alerts. Choose which of the case's alerts to include in this STR. Every transaction and party used later in the wizard is pulled from whichever alerts are selected here, so it's worth confirming this before moving on.

Step 2 — Report Type. This step covers everything GoTRACS needs to know about the filing itself, not the case. STR Type is usually Regular STR for most cases — High Priority, Bulk Report, Per Account, and Highly Unusual exist for specific regulatory scenarios (kidnapping, trafficking, and similarly urgent categories use High Priority, for example). Submission Type is almost always "New" for a first-time filing.

Date of determination is the date the covered person knew, or should have known, the transaction was suspicious. This date starts the regulatory filing-deadline clock.

Supervising agency identifies the regulator this report is being filed with.

STR trigger records what actually prompted the filing — a proactive review, a watchlist match, a freeze order, and so on.

Once every field in this step is filled in, the filing deadline is calculated automatically and shown live.

Step 3 — Reason for Suspicion. Select one or more codes describing why the activity is suspicious, from a list of 43 standardized Suspicious Circumstance (SC), Predicate Crime (PC), and Money Laundering (MC) codes.

Some codes carry extra requirements — a KYC REQ tag means additional KYC documentation must be on file before that particular code can be used. An optional Additional reason codes section further down lets you add secondary codes beyond your primary selection, then Next Step continues once every relevant code has been selected.

Step 4 — Transaction. Every transaction attached to the selected alert(s) appears here, pre-selected by default. Filter by type if the list is long.

A date range narrows the list further to transactions within a specific period, useful when a case spans many transactions over time.

Step 5 — Subject Parties. Parties are auto-derived from the transactions selected in Step 4 — nothing to add manually in most cases. Click a party's row to expand it and confirm their details.

Entity Type distinguishes an individual from a corporate or other legal structure.

Step 6 — Narratives. The final step is a free-text narrative explaining the filing in plain language. GoTRACS expects a narrative that answers who is involved, what the activity was, when and where it occurred, why it's suspicious, and how it was carried out — a minimum of 200 characters is required, and the character counter confirms when that bar is met.

Once the narrative meets the minimum length, Complete STR becomes clickable.

How to use

  • Work through all 6 steps — Select Alerts, Report Type, Reason for Suspicion, Transaction, Subject Parties, Narratives — using Next Step to advance
  • Save as draft is available at every step if the filing needs to be finished later
  • Click Complete STR once the narrative meets the 200-character minimum

Once completed, the case's Status updates one final time to STR Created, and the File STR button is replaced by Download STR — the filed report can now be downloaded at any time, and the case can still be re-opened later if needed.

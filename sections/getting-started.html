Getting Started

FT AML is an Anti-Money Laundering (AML) platform that helps financial institutions detect suspicious activity, screen customers against regulatory watchlists, monitor transactions, manage investigations, and comply with AML/CTF regulations.

Platform Objectives

FT AML is built around a core set of objectives:

  • Detect suspicious financial transactions by continuously monitoring customer and transaction activity
  • Support banks and financial institutions in complying with applicable AML and Counter-Terrorist Financing (CTF) regulations
  • Assess and calculate customer risk based on configurable risk parameters and business rules
  • Generate timely alerts for unusual or potentially suspicious activity requiring further investigation
  • Enable compliance teams to efficiently investigate, manage, and resolve AML cases
  • Minimize false positive alerts through intelligent rule design and optimized risk assessment
  • Deliver a scalable, configurable AML platform comparable to leading AML solution providers

Login

Navigation Platform URL → Login

  • Navigate to the FT AML Platform URL
  • Enter your email and password
  • Click Sign in
  • You will receive an OTP to verify your identity — enter it to complete login
  • Once verified, you will land on the Homepage, the entry point to all modules
  • Use Forgot Password if login fails after verifying credentials

Secure authentication is the first line of defense for sensitive AML data, and every login is tied to a user account — supporting audit requirements by recording who created, modified, or closed an AML investigation.

Homepage

Navigation Login → Homepage

After entering valid credentials, the user is redirected to the Homepage. This is the central workspace for compliance teams, giving quick access to every AML module from one place and reducing time spent switching between investigations, screening, and monitoring activities.

Roles & Access

Every screen in FT AML is gated by the logged-in user's role — what a user sees on login, which module tabs they can open, and which actions are available to them all follow directly from the role assigned in Admin → Roles & Permissions.

  • Compliance Analyst — reviews alerts and screening hits and conducts first-level investigation. Sees only My Queue in Case Manager and Alert Manager, can run Watchlist Search and Manual Screening, and can close a case as False Match — but cannot approve an STR or edit any configuration screen.
  • Compliance Officer / MLRO — has all Compliance Analyst access plus All Cases / All Alerts visibility across the institution, reassignment rights from Admin View, sign-off authority on any case escalated as a True Match, and is the only role that can approve an STR filing in STR Listing.
  • AML Configuration Admin — the only role with edit access to Screening Configuration, Alert Configuration, and Transaction Monitoring rules/variables; maintains weightages, severity bands, rules, and typologies. Does not action alerts or cases directly.
  • IT / Platform Admin — manages user accounts and role assignment, data ingestion schedules, and overall platform availability; has access to Admin and Hierarchy Management but not the AML-specific configuration screens reserved for Configuration Admins.

Module Overview

After logging in, users can access the full range of FT AML modules from the FT AML menu. The hierarchy below shows how the modules and their sub-features are organized, so you know where to find each feature before exploring it in detail.

  • Homepage — Dashboard, the landing workspace after login, giving an at-a-glance view of platform health, alert volume, and case load
  • Customer Management — onboards and maintains a single source of truth for every customer profile screened or monitored elsewhere in the platform
  • FT AML — Case Manager, Alert Manager, STR Listing, AI Manager, Name Screening (Watchlist Search, Manual Screening, Batch Screening, Delta Screening, Configuration → Alerts / Screening), Transaction Monitoring & Rule Engine (Typology, Variables, Schedules), Data Ingestion (Watchlist, TMS)
  • Reports — filter, export, and share operational and regulatory reporting drawn from Case Manager, Alert Manager, and STR Listing data
  • Admin — profile, roles, and platform-wide settings, including User Management
  • Hierarchy Management — organizational reporting structure and escalation paths

Which of these a given user actually sees depends on their assigned role — see Roles & Access for how access is scoped per module.

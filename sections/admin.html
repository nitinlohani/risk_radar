Administration

Admin

Navigation Homepage → Admin

The platform-wide settings area — separate from the module-specific configuration screens covered elsewhere in this guide. Covers your own account, who can do what across the platform, and the organizational reporting structure everything else routes through.

Profile & Preferences

  • Edit your display name, email, and contact details
  • Update notification preferences — e.g. which alert severities trigger an email
  • Change password and manage login security settings

Roles & Permissions

Controls who can see and do what across the platform, aligned to the roles introduced in Roles & Access:

  • Assign each user a role — Compliance Analyst, Compliance Officer/MLRO, AML Configuration Admin, or IT/Platform Admin
  • Restrict access to sensitive configuration screens (screening weightages, alert severity bands, transaction monitoring rules) to Configuration Admins only
  • Control which users can approve STR filings, restricted to Compliance Officers/MLROs

Configuration Access

Admin is also the hub that links out to every configuration screen covered elsewhere in this guide, rather than duplicating them:

  • Screening weightages and severity bands — see Name Screening → Configuration
  • Transaction monitoring rules and variables — see Transaction Monitoring & Rule Engine
  • Automatic case-creation rules — see Automation → Case Creation
  • Organizational reporting structure — see Hierarchy Management, below

Hierarchy Management

Navigation Homepage → Admin → Hierarchy Management

Defines the organizational reporting structure that AML operations run on top of — who sits above whom, and which unit or branch each user and case belongs to. Screening, monitoring, and case data all inherit this structure, which is what makes role-based routing and escalation possible elsewhere in the platform.

  • Define organizational units (e.g. branch, region, department) and the parent-child relationships between them
  • Assign users to a position within the hierarchy, establishing their reporting line and supervisor
  • Drive case and alert escalation paths — e.g. an unresolved case escalates automatically to the assignee's supervisor as defined here
  • Support segregation-of-duties and maker-checker controls by making reporting relationships explicit and auditable
  • Feed dashboard and SLA reporting that needs to be sliced by branch, team, or region
